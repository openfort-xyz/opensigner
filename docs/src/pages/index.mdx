# OpenSigner: open-source, non-custodial wallet key management

OpenSigner is an open-source, self-hostable key management system that issues non-custodial
cryptographic keys to your users. Instead of storing a private key in one place, OpenSigner splits
each key into three shares using [Shamir's Secret Sharing](https://en.wikipedia.org/wiki/Shamir%27s_secret_sharing):
one share stays on the user's device, one lives in hot storage, and one (encrypted) lives in cold
storage. The full key is only ever reconstructed in memory inside a sandboxed iframe and is discarded
immediately after each signing operation, so neither you nor any single component can act on a user's
behalf.

This model gives developers a way to offer self-custody without asking users to manage seed phrases.
Because every component is open source and can be self-hosted, you control the trust boundaries: you can
run the entire stack yourself, or split responsibility across parties so that no operator ever holds
enough shares to recover a key alone. OpenSigner is built by [Openfort](https://www.openfort.io), and
the full source is available on [GitHub](https://github.com/openfort-xyz/opensigner).

## How it works

OpenSigner is made up of an [iframe component](/components/iframe) that performs key generation,
splitting, and ephemeral reconstruction; [hot](/components/hot_storage) and cold storage for the
remaining shares; and an [authentication service](/components/auth) that issues access tokens. Together
they implement a non-custodial signer where the private key never persists outside the user's session.
For the cryptographic background, see the original Shamir paper, ["How to Share a Secret"](https://dl.acm.org/doi/10.1145/359168.359176)
(Communications of the ACM, 1979).
